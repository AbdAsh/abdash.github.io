# Concierge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An embedded voice agent on the AI tab that answers questions about the author's experience out loud, over a voice loop built rather than rented. Replaces the "Coming Soon" card on `abdash.net`.

**Architecture:** The island lives in the **portfolio site repo** (`abdash.github.io`), since it is embedded in the Astro AI tab. Browser `SpeechRecognition` captures input, a Supabase Edge Function `concierge-turn` streams an answer from OpenRouter with the full dossier in context, and `SpeechSynthesis` speaks it. Turn-taking, barge-in and interrupt handling are implemented here — that is the engineering being claimed.

**Tech Stack:** Astro island (React) · Web Speech API · Supabase Edge Function · OpenRouter `MODEL_CHEAP`.

## Global Constraints

- **This is the only project split across two repos.** The island is in `abdash.github.io`; the Edge Function is in `abdash-labs`.
- **The only unauthenticated surface in the program.** A visitor to `abdash.net` has no Supabase session, because that lives on `labs.abdash.net`. Rate limiting is therefore **per-IP via `platform.rate_limits`**, not per-user quota.
- **No retrieval layer.** The whole dossier fits in context. Recto is the project that demonstrates RAG; imitating it here would be worse.
- **ElevenLabs is not used.** The account's 10,000 monthly characters are reserved for Recto's audio overviews.
- Origin check: only `https://abdash.net` may call the function.
- No conversation is ever persisted.
- Commit trailer: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

- [ ] **Step 1: Write the failing rate-limit tests**

```ts

Deno.test('throws on the request past the limit', async () => { ... })
```

- [ ] **Step 2: Implement `checkRateLimit` against `platform.rate_limits`**

Uses `serviceClient()` — permitted here because there is no caller JWT to act as. Window start is the current time floored to `windowSec`. Upsert-and-increment, then compare. Default policy: **20 turns per IP per hour**.

Derive the IP from `x-forwarded-for`, taking the first entry, and hash it before storing — the bucket key should not be a plaintext visitor IP.

- [ ] **Step 3: Write the function**

```ts

You never claim to be him. Answer only from the dossier below. Keep answers to three sentences \
or fewer unless asked to elaborate. If something is not in the dossier, say you do not know and \

DOSSIER
-------
${DOSSIER}`
```

Order: `preflight` → origin check against `https://abdash.net` → `checkRateLimit(hashedIp, 20, 3600)` → `chatStream` with the system prompt, prior turns and the question → stream tokens back. No `\f` prefix here; there are no citations, so the body is plain tokens.

## Task 3: The voice loop

**Repo:** `abdash.github.io`

**Files:**
- Create: `src/components/concierge/voice.ts`, `voice.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type VoiceState = 'idle' | 'listening' | 'thinking' | 'speaking'
  export interface VoiceLoop {
    start(): void; stop(): void
    onState(cb: (s: VoiceState) => void): void
    onTranscript(cb: (text: string, final: boolean) => void): void
  }
  export function createVoiceLoop(opts: { ask: (q: string) => AsyncIterable<string>; silenceMs?: number }): VoiceLoop
  export function isSpeechSupported(): boolean
  ```

This is the task the whole project exists to demonstrate. Build it as an explicit state machine, not nested callbacks.

- [ ] **Step 1: Write the failing state-machine tests with a fake recognition backend**

```ts
describe('voice loop', () => {
  it('moves idle → listening → thinking → speaking → listening across one turn', async () => { ... })

  it('ends a turn on sustained silence, not on the API onend event', async () => {
    // onend fires spuriously in Chromium; the loop must restart recognition
    // and keep listening rather than treating it as end-of-turn
  })

  it('restarts recognition after a spurious onend without emitting a turn', () => { ... })

  it('cancels synthesis within 200ms when the user speaks over it', async () => {
    loop.state = 'speaking'
    fakeRecognition.emitInterim('actually wait')
    expect(synthesisCancelled).toBe(true)
    expect(loop.state).toBe('listening')
  })

  it('does not treat its own synthesised audio as user speech', () => {
    // guard against the echo loop: interim results arriving with no mic energy
    // change while speaking must be ignored below a confidence floor
  })

  it('drops duplicate final results for the same utterance', () => { ... })
})
```

The spurious-`onend` case and the self-echo case are the two bugs that make a hand-built voice loop feel broken, and both are invisible until tested.

- [ ] **Step 2: Implement the state machine**

- Interim results plus a silence timer (default 900 ms) decide end-of-turn.
- Recognition is restarted automatically on `onend` while the loop is active, with a guard so one utterance cannot fire twice.
- During `speaking`, recognition stays active; a confident interim result cancels `speechSynthesis` immediately and transitions to `listening`.
- Answers are spoken in sentence-sized chunks as tokens stream, so speech begins before the full response arrives.

- [ ] **Step 3: Run the tests, then verify barge-in by hand with a real microphone**

Interrupting mid-sentence must stop synthesis within roughly 200 ms. This cannot be proven by unit test alone.

- [ ] **Step 1: Idle state**

Mic icon, "Interview my AI", and three suggested questions. **Nothing loads until click** — the island is lazy-imported and no microphone permission is requested before consent.

- [ ] **Step 2: Active state**

Listening and speaking indicators, a live transcript line, an end-call button, a text-input toggle, and a five-minute session cap with a visible timer near the end.

- [ ] **Step 3: Text fallback**

Same endpoint, no speech APIs. Shown automatically when `isSpeechSupported()` is false, and reachable at any time via the toggle. Safari and Firefox land here.

- [ ] **Step 4: Privacy note under the widget**

State plainly that speech recognition is processed by the browser's provider (Google, in Chromium) and that nothing is stored. Do not soften this — it is the honest cost of the free transport.

- [ ] **Step 5: Failure states**

Microphone denied, unsupported browser, rate limited. Each must land somewhere usable, never a broken widget.

- [ ] **Step 6: Consolidate the dead `AiSection.astro`**

The AI panel is inlined in `index.astro`; there must be exactly one source of truth after this task.
