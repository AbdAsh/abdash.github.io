# RAG Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Benchmark chunking, embedding and retrieval configurations side by side with hit@k and MRR against labeled gold spans, and publish the result as a permalink. Deployed at `labs.abdash.net/raglab`.

**Architecture:** Everything except embedding runs in the browser. Chunkers are pure TypeScript; the run engine orchestrates client-side; embeddings go through `raglab-embed`; vectors are cached in **IndexedDB and never sent to Postgres**. The server stores only configuration, question sets, gold spans and computed metrics.

**Tech Stack:** Vite 8 · React 19 · TypeScript 6 · `@labs/doc-core` · `idb` · `vega-lite` · `@labs/platform`.

## Global Constraints

- **Prerequisites: the platform plan and Recto Task 1 (`@labs/doc-core`) are complete.**
- **No vector may be written to Postgres.** A twelve-config run over a hundred-page document is ~11 MB of embeddings; 45 such runs would consume the entire 500 MB shared database. This is the single most important constraint in this plan.
- Embeddings via `raglab-embed` → OpenAI. Models compared in v1: `text-embedding-3-small` (1536) and `text-embedding-3-large` (3072).
- Budget: 30 MB Postgres, 50 MB Storage.
- Vite `base: '/raglab/'`.

## Task 1: Chunker families

**Files:**
- Create: `apps/raglab/src/lib/chunkers.ts`, `chunkers.test.ts`

**Interfaces:**
- Consumes: `chunkPages`, `Page`, `Chunk` from `@labs/doc-core`.
- Produces:
  ```ts
  export interface SpanChunk extends Chunk { start: number; end: number }   // char offsets into full text
  export type ChunkerId = 'fixed' | 'sentence-window' | 'recursive'
  export interface ChunkerParams { size: number; overlap: number }
  export function chunkWith(id: ChunkerId, text: string, p: ChunkerParams): SpanChunk[]
  export const CHUNKERS: { id: ChunkerId; label: string }[]
  ```

**The critical addition over `doc-core`:** every chunk carries `start` and `end` character offsets into the *full document text*. Gold spans are also character ranges, so overlap is computable across different chunkings — which is the whole reason the metrics are comparable.

- [ ] **Step 1: Write the failing tests**

```ts
import { describe, it, expect } from 'vitest'
import { chunkWith } from './chunkers'

const text = 'Alpha beta gamma. Delta epsilon zeta. Eta theta iota. Kappa lambda mu.'

describe('span accounting', () => {
  it('produces offsets that slice back to the chunk content', () => {
    for (const id of ['fixed', 'sentence-window', 'recursive'] as const) {
      for (const c of chunkWith(id, text, { size: 30, overlap: 10 })) {
        expect(text.slice(c.start, c.end)).toBe(c.content)
      }
    }
  })

  it('covers the whole document with no gap between consecutive chunks', () => {
    const cs = chunkWith('fixed', text, { size: 30, overlap: 0 })
    expect(cs[0]!.start).toBe(0)
    expect(cs[cs.length - 1]!.end).toBe(text.length)
    for (let i = 1; i < cs.length; i++) expect(cs[i]!.start).toBeLessThanOrEqual(cs[i - 1]!.end)
  })

  it('overlaps by roughly the requested amount', () => {
    const cs = chunkWith('fixed', text, { size: 30, overlap: 10 })
    expect(cs[0]!.end - cs[1]!.start).toBeGreaterThan(5)
  })

  it('sentence-window never splits mid-sentence', () => {
    for (const c of chunkWith('sentence-window', text, { size: 40, overlap: 0 })) {
      expect(c.content.trim()).toMatch(/[.!?]$/)
    }
  })
})
```

The round-trip assertion — `text.slice(start, end) === content` — is what makes every later metric trustworthy. If it fails, every score is meaningless.

- [ ] **Step 2: Run, confirm failure, implement all three chunkers**

`fixed` wraps `doc-core`'s chunker with offset tracking. `sentence-window` splits on sentence boundaries and groups until `size`. `recursive` splits on paragraphs, then sentences, then hard-wraps.

## Task 2: Gold spans and metrics

**Files:**
- Create: `apps/raglab/src/lib/metrics.ts`, `metrics.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface GoldSpan { start: number; end: number }
  export interface Question { id: string; text: string; gold: GoldSpan }
  export function overlapRatio(chunk: SpanChunk, gold: GoldSpan): number
  export function isHit(chunk: SpanChunk, gold: GoldSpan, threshold?: number): boolean
  export function hitAtK(ranked: SpanChunk[], gold: GoldSpan, k: number, threshold?: number): boolean
  export function reciprocalRank(ranked: SpanChunk[], gold: GoldSpan, threshold?: number): number
  export function aggregate(perQuestion: { hit: boolean; rr: number }[]): { hitRate: number; mrr: number }
  ```

`overlapRatio` is *intersection over gold length*, not over chunk length — a chunk containing the whole gold span is a hit regardless of how much extra it carries.

- [ ] **Step 1: Write the failing tests against handcrafted fixtures**

```ts
const gold = { start: 100, end: 200 }
const chunk = (start: number, end: number) => ({ start, end, content: '', page: 1, index: 0 })

describe('overlapRatio', () => {
  it('is 1 when the chunk fully contains the gold span', () => {
    expect(overlapRatio(chunk(0, 500), gold)).toBe(1)
  })
  it('is 0 when disjoint', () => {
    expect(overlapRatio(chunk(0, 99), gold)).toBe(0)
  })
  it('is 0 for a chunk ending exactly at the gold start', () => {
    expect(overlapRatio(chunk(0, 100), gold)).toBe(0)     // half-open ranges
  })
  it('is 0.5 for half coverage', () => {
    expect(overlapRatio(chunk(150, 400), gold)).toBe(0.5)
  })
  it('handles a gold span smaller than the chunk boundary offset', () => {
    expect(overlapRatio(chunk(190, 300), gold)).toBeCloseTo(0.1)
  })
})

describe('reciprocalRank', () => {
  it('is 1 when the first result hits', () => { ... })
  it('is 1/3 when the third result hits', () => { ... })
  it('is 0 when nothing hits', () => { ... })
})

describe('isHit at the threshold boundary', () => {
  it('counts exactly 50% as a hit at the default threshold', () => {
    expect(isHit(chunk(150, 400), gold, 0.5)).toBe(true)
  })
  it('rejects 49%', () => {
    expect(isHit(chunk(151, 400), gold, 0.5)).toBe(false)
  })
})
```

The half-open-range case and the exact-threshold case are the two off-by-one traps in this whole project.

- [ ] **Step 1: Suggest via `chatJSON` through a small proxy**

The model returns a question plus the **verbatim passage** that answers it. The client then locates that passage with `text.indexOf` to derive real offsets — asking a model for character indices directly is unreliable, and locating the quote ourselves makes the offsets correct by construction.

`validateGold` rejects any suggestion whose quote is not found; those are dropped rather than shown.

## Task 7: Schema, persistence and permalinks

**Files:**
- Create: `supabase/migrations/0004_raglab.sql`
- Create: `tests/rls/raglab.test.ts`

- [ ] **Step 1: Write the migration**

```sql
create schema if not exists raglab;
grant usage on schema raglab to anon, authenticated, service_role;

create table raglab.experiments (
  id          uuid primary key default gen_random_uuid(),
  slug        text unique not null,
  owner_id    uuid not null references auth.users(id) on delete cascade default auth.uid(),
  doc_name    text not null,
  doc_fingerprint text not null,
  doc_path    text,                      -- Storage path, null for local-only runs
  questions   jsonb not null,            -- [{id, text, gold:{start,end}}]
  created_at  timestamptz not null default now()
);

create table raglab.runs (
  id            uuid primary key default gen_random_uuid(),
  experiment_id uuid not null references raglab.experiments(id) on delete cascade,
  owner_id      uuid not null references auth.users(id) on delete cascade default auth.uid(),
  results       jsonb not null,          -- ConfigResult[] — metrics only, NEVER vectors
  created_at    timestamptz not null default now()
);

alter table raglab.experiments enable row level security;
alter table raglab.runs        enable row level security;

create policy experiments_own on raglab.experiments for all to authenticated
  using (owner_id = auth.uid()) with check (owner_id = auth.uid());
create policy experiments_public on raglab.experiments for select to anon, authenticated
  using (true);
create policy runs_own on raglab.runs for all to authenticated
  using (owner_id = auth.uid()) with check (owner_id = auth.uid());
create policy runs_public on raglab.runs for select to anon, authenticated
  using (true);

grant select, insert, update, delete on raglab.experiments, raglab.runs to authenticated;
grant select on raglab.experiments, raglab.runs to anon;
```

Permalinks require public read; that is intentional and disclosed in the UI before a run is saved.
